# Proposed AI-evaluation tasks for scientific visualization

> **Status: a proposed benchmark.** No AI system has been run against these tasks, no results exist, and nothing here is a
> production-scale evaluation. The tasks are designed so that reference answers can be checked against files and numbers
> produced by this repository. Items that involve ParaView behaviour that the author has **not** executed are marked
> *(unverified in ParaView)*; a grader should confirm those by running the code before scoring on them.

**Design principles.** Each task (a) mirrors work a ParaView specialist does, (b) has an answer that can be checked
objectively, (c) contains at least one trap where a plausible-sounding answer is wrong, and (d) separates *what the data
support* from *what they do not*. Scoring is out of 10 per task with all-or-nothing criteria so two graders agree.

---

## Task 1: Identify the velocity arrays in an unfamiliar dataset

**Prompt.** "I have `fields.vtk` (legacy VTK, STRUCTURED_POINTS, 64×64×64, POINT_DATA). The reader reports these point arrays:
`velocity` (3 components), `vorticity` (3), `Q_numpy` (1), `lambda2_numpy` (1), `speed` (1). I need to colour a slice by velocity
magnitude and later compute vorticity in ParaView. Which array do I use, is it point or cell data, which arrays are
derived and from what, and how do I check that the three components are in the right order before trusting any derived field?"

**Required input files.** `results/synthetic_validation/fields.vtk` (generated by
`python scripts/analyze_spatial_fields.py --synthetic taylor_green --n 64 --out-dir results/synthetic_validation`) and
`results/synthetic_validation/spatial_summary.json`. The data are a **synthetic analytic Taylor–Green flow**, used only so the key is checkable.

**Expected output.** `velocity` (point data) is the source field; `vorticity`, `Q_numpy`, `lambda2_numpy`, `speed` are derived
from it. Colour by `velocity` with component *Magnitude* (or use `speed`, which equals it). Do not use `vorticity` merely because it is also
a 3-vector. Component-order/axis check: compute divergence of the field; for an incompressible flow the RMS divergence
should be negligible compared with the RMS vorticity.

**Reference solution.**
1. Read the file header (`head -c 400 fields.vtk`) or the reader's Information panel: arrays are listed under POINT_DATA, so the data are point-centred.
2. `velocity` is the only array that is not named as derived and that the others are computed from (`speed = |velocity|`; `vorticity = curl velocity`).
3. Check: `spatial_summary.json` reports `divergence_rms_over_vorticity_rms ≈ 8e-16` for this field. A permuted-axis or wrong-spacing field would give a large ratio.
4. Colouring: `ColorBy(display, ('POINTS', 'velocity', 'Magnitude'))`. In this file speed ranges 0 to 1.0 (mean 0.431).

**Scoring (10).** 2 – names `velocity` as the field to colour by. 2 – states point-centred and gives the evidence (header/Information panel).
2 – correctly identifies the other four arrays as derived (partial credit not allowed unless all four). 2 – proposes a divergence or equivalent physical
consistency check rather than only checking shapes. 2 – uses magnitude component for colouring.

**Common failure modes.** Choosing `vorticity` because it has 3 components; claiming cell data; recommending a Calculator `sqrt(velocity_X^2+…)` without checking array names; proposing to "check components" by eyeballing a plot.

## Task 2: Design a ParaView workflow to visualize a 3-D velocity field

**Prompt.** "A 128³ cutout of homogeneous isotropic turbulence is loaded as point data `velocity`. Give an ordered ParaView
(`paraview.simple`) workflow to examine it: what to show, which filters, in what order, what colour-range and camera policy to use if I compare several
time steps, and which filters you would deliberately *not* use and why. Write the key script lines."

**Required input files.** `paraview/turbulence_pipeline.py` is the reference *(unverified in ParaView)*; the prompt needs no file.

**Expected output.** An ordered workflow with justification: inspect (bounds, arrays, centring, time steps) → colour by |u| on an
outline/slice with a **fixed** colour range → slice → arrows on the slice (subsampled) → Stream Tracer from a seed cloud → vorticity/Q via Gradient → Contour on Q at several thresholds.
For time comparisons: fix the LUT range (`AutomaticRescaleRangeMode = 'Never'`) and the camera. Reject: volume rendering of |u| as a primary figure
(opacity mapping is arbitrary and hides structure), glyphs on all 128³ points (illegible), a single unexplained Q threshold.

**Reference solution.** See `paraview/turbulence_pipeline.py` for the script: `OpenDataFile` → `Slice(SliceType='Plane')` → `Glyph(GlyphType='Arrow', Stride=…)` →
`StreamTracer(SeedType='Point Cloud')` → `Gradient(ScalarArray=['POINTS','velocity'], ComputeVorticity=1, ComputeQCriterion=1)` → `Contour(ContourBy=['POINTS', <Q name>])`.

**Scoring (10).** 2 – begins with inspection of arrays/centring/bounds. 2 – fixed colour range and camera for multi-time comparison. 2 – Slice and Stream Tracer
used with a reason each. 2 – uses a derived rotation field (Gradient→Q or λ₂) with several thresholds, not only |ω|. 2 – names at least two filters not to use blindly
with reasons (e.g. all-points glyphs, one arbitrary isovalue). Script lines must use real `paraview.simple` names; deduct 1 per invented property up to 2 *(grader should check against the installed version)*.

**Common failure modes.** Auto-rescaling the colour map per time step; stream tracing from a single seed and generalising; calling streamlines "particle paths"; omitting the centring check; listing many filters with no purpose.

## Task 3: Choose a method to visualize rotational structures

**Prompt.** "I want to show vortex tubes in a turbulence cutout. A colleague says to draw an isosurface of vorticity magnitude. Is that adequate? Compare it
with Q-criterion and λ₂, state the formulas, how to choose thresholds, and what you can and cannot conclude from the picture."

**Required input files.** `results/synthetic_validation/threshold_sensitivity.csv` and `docs/methodology.md` §3 (synthetic data again; only for the numeric illustration).

**Expected output.** Vorticity magnitude highlights shear layers as well as swirl, so it can mark non-vortical regions. Q = ½(‖Ω‖² − ‖S‖²) (Q > 0 = rotation dominates);
λ₂ = middle eigenvalue of S²+Ω² (λ₂ < 0 for a vortex core). Both are Galilean-invariant; both are threshold-dependent and need not agree. Choose thresholds as several multiples of a
field statistic (e.g. Q_rms) and **report** the reference and the sensitivity. Conclusion limit: the picture shows regions where rotation dominates strain at that threshold; it does not show energy transfer or prove vortex tubes.

**Reference solution (numbers from the repo).** Taylor–Green (synthetic): Q_rms = 0.305; volume fraction of {Q > f·Q_rms} is 0.213 (f=0.5), 0.127 (1), 0.040 (2), and 0 (4, 8); component count 12 at the first three thresholds.
The sweep shows that the same flow gives a volume that varies five-fold across a factor-of-four range of threshold, and that thresholds above ≈ 3.3·Q_rms (max Q = 0.997) select nothing.

**Scoring (10).** 2 – says vorticity magnitude alone is not adequate and gives the shear-layer reason. 2 – correct Q definition. 2 – correct λ₂ definition/criterion. 2 – proposes a multi-threshold sweep with a stated reference
statistic. 2 – states a limit on conclusions (not proof of vortices; no energy-transfer claim; resolution/gradient error).

**Common failure modes.** Q defined with the wrong sign or as |S|²−|Ω|²; "λ₂ > 0 marks vortices"; one threshold with no justification; claiming hairpin vortices or "the cascade is visible"; ignoring that gradients are computed numerically.

## Task 4: Debug a ParaView Python script

**Prompt.** "This script should draw a Q-isosurface of the field in `fields.vtk` but renders nothing / errors. Find every bug and give the corrected script. Dataset facts: the
velocity array is `velocity` and it is POINT data."

```python
from paraview.simple import *
r = OpenDataFile('fields.vtk')
grad = Gradient(Input=r)
grad.ScalarArray = ['CELLS', 'velocity']
grad.ComputeQCriterion = 1
grad.QCriterionArrayName = 'Q_pv'
con = Contour(Input=grad)
con.ContourBy = ['POINTS', 'Q Criterion']
con.Isosurfaces = [0.3]
Show(con)
Render()
```

**Required input files.** `results/synthetic_validation/fields.vtk`; a ParaView 6.x installation to run the key.

**Expected output.** Two bugs. (1) `ScalarArray` points at a *cell* array named `velocity`; it must be `['POINTS', 'velocity']`. (2) The Q array was renamed to `Q_pv` but `ContourBy` still
requests `'Q Criterion'`; use `['POINTS', 'Q_pv']`. Additionally (advice, not a bug): `0.3` is meaningful only relative to this field's Q_rms (0.305 for the synthetic flow); state the reference. A good answer also adds `Show(r)` outline or a view reset.

**Reference solution.**
```python
grad = Gradient(Input=r)
grad.ScalarArray = ['POINTS', 'velocity']
grad.ComputeQCriterion = 1
grad.QCriterionArrayName = 'Q_pv'
con = Contour(Input=grad)
con.ContourBy = ['POINTS', 'Q_pv']
con.Isosurfaces = [0.305]          # ≈ 1.0 × Q_rms for the synthetic Taylor–Green field
Show(con); Render()
```
*(unverified in ParaView: property names are from the 6.x API as the author understands it; the grader should run the key and the buggy script and record the actual symptom.)*

**Scoring (10).** 3 – finds bug 1 with the point/cell reason. 3 – finds bug 2 with the renamed-array reason. 2 – corrected script is runnable *(grader runs it)*. 2 – notes that the isovalue needs a stated reference/range, e.g. checks the array range via `grad.PointData['Q_pv'].GetRange()`.

**Common failure modes.** "Fixing" by renaming the array to `Q Criterion` *and* leaving `CELLS`; adding `UpdatePipeline()` as the fix; rewriting with a Calculator and numpy without addressing the cause; claiming a bug in `OpenDataFile`; inventing properties.

## Task 5: Does a spectrum plot support this scientific claim?

**Prompt.** "A report shows the radial energy spectrum E(k) of forced isotropic turbulence on log-log axes (k = 1 … 482) and states: (a) 'the spectrum follows Kolmogorov's −5/3 law, confirming a fully developed
inertial cascade'; (b) 'the field contains hairpin vortices'; (c) 'energy is concentrated at the largest scales'. Evaluate each claim: supported by this plot, partly supported, or requires spatial data? Justify with numbers."

**Required input files.** `data/spectrum.txt`, `results/figures/fig_energy_spectrum_loglog.png`, `results/tables/spectrum_fit_sensitivity.csv`, `results/tables/summary_results.json`.

**Expected output.**
* (a) **Not established.** Fitted slopes depend on range: −1.57 (k=3–10), −1.59 (3–23), −1.73 (5–15), −1.44 (10–30), −1.45 (10–50), −1.53 (20–60), −1.60 (30–57), −1.96 (30–100). The compensated spectrum k^{5/3}E is only roughly flat
  (varies by a factor 1.66 over k=3–60, 0.288 at k=3 to 0.477 at k=45, with a broad maximum near k=45). "Approximately a power law with exponent ≈ −1.4 to −1.7 over k ≈ 3–60, roughly consistent with but not establishing −5/3" is defensible; "confirms −5/3" and "fully developed cascade" are not (a spectrum alone does not show energy flux).
* (b) **Requires spatial data**, and even then needs evidence beyond a vorticity/Q picture; hairpins are not a feature expected to be claimed for isotropic turbulence from this evidence. A 1-D spectrum has no phase or structure information.
* (c) **Supported:** E(1) = 0.300, E(2) = 0.130, a drop of a factor ≈ 2,050 from k=1 to k=100; the low-k shells (k ≤ 2) are the forced ones per JHTDB. Caveat: this is the *spectral distribution*; "concentrated" means relative to higher k, not that structures are spatially localised.
* Also acceptable to note: the upturn after k = 447 (minimum E = 2.43e-7) is a data feature that should not be physically interpreted.

**Scoring (10).** 3 – (a) judged not established (not simply "false") with at least two range-dependent slopes cited or the compensated-spectrum variation (factor ≈ 1.4–1.7). 2 – (b) judged as requiring spatial data and not supported by a spectrum. 2 – (c) judged as supported
with a number. 1 – mentions high-k upturn or range choice caveat. 2 – states that the summary files cannot reconstruct the velocity field.

**Common failure modes.** Accepting −5/3 because a dashed reference line "looks parallel"; fitting a single hand-picked range and reporting it as the law; treating energy ≠ structure; saying (b) is "plausible"; ignoring that a spectrum has no spatial information.
